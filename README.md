# Energy errors on transition paths set the kinetic accuracy of machine-learned interatomic potentials

Code and data for the paper of the same name (Xiyao Yu, Nanyang Technological University).

Every number and every figure in the paper and its Supporting Information can be reproduced from what is here.
Raw molecular-dynamics trajectories are not deposited: they run to several gigabytes and are regenerated by the
notebooks in `colab/` with the seeds the scripts carry. The quantities derived from them (hop events,
committor increments, per-frame energy errors and rates) are all included.

## Layout

The tree is the one the scripts expect, so every program here runs unmodified from the directory it sits in.

| | |
|---|---|
| `*.py` (top level) | one- and two-dimensional numerical experiments: exact generators, intervals, friction, diffusion, label placement, kinetic loss. Run from the top level; they write into `data/` |
| `ala2/` | alanine dipeptide: teacher and student dynamics, force errors, predictions, acquisition, and the student networks (`student_*.pt`) |
| `li3ocl/` | Li<sub>3</sub>OCl: hop analysis, defect states, reactive dissipation density, intervals |
| `colab/` | the production runs as executed (Google Colab notebooks), the batched molecular-dynamics engine, the MACE teacher and students, and equilibrium frames |
| `research_extensions/` | nonlinear response and corrected trial fields (`response_geometry*.py`); force errors weighted by the response flux (`work_weighted/`) |
| `dft/` | density-functional single points: inputs, energies (`E0`, extrapolated to zero smearing), magnetic moments and structures of the hop-path and equilibrium frames of the teacher; `excluded_fused_pairs.txt` lists the hop frames with a fused lithium pair, which were not computed |
| `data/` | analysis outputs, including the predictions computed from reference data (`*_predicted*`, `li3ocl_pred_*`) |
| `figs/` | `fig1_overview.py`, which computes and draws Figure 1; `structures.py`, which selects and projects the configurations of Figures 4a,b and 5a,b; `dft_panel_data.py`, which computes Figure 5d; and `data/`, the numerical values behind every figure |

## Reproducing

The one- and two-dimensional experiments need only NumPy and SciPy and run in minutes:

```
python doublewell_check.py
python bracket_check.py
cd research_extensions/work_weighted && python flux_checks.py
```

Alanine dipeptide needs OpenMM 8.6 and PyTorch; Li<sub>3</sub>OCl needs MACE and PyTorch. Analyses that read
derived data only, such as

```
cd li3ocl && python bracket_vs_rate.py
```

run against `data/` with no simulation at all. The scripts that need raw trajectories or stored hop frames are
`ala2/series_weights_check.py`, `ala2/model_side_all.py`, `ala2/measure_twoc.py` and, in `li3ocl/`, `analyze_hops.py`, `defect_states.py`, `clean_channel.py`,
`dV_profile.py`, `student_side.py`, `student_paths.py`, `select_two_sided.py`, `lattice_integrity.py` and `students_table.py`;
regenerate the trajectories with the notebooks in `colab/` first. `li3ocl/mp0_vs_dft.py` needs mace-torch, which fetches MACE-MP-0 (small) on first use; `figs/structures.py` redraws Figures 4a,b and 5a,b from the stored frames in `figs/data/`.
